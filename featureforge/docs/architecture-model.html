Full system model — built and planned, together

The complete target architecture from the roadmap in one picture: FeatureForge itself (top), what it writes into each stream's target directory (middle), and where that ultimately deploys (bottom). Filled ● marks what runs today; hollow ○ marks what's still ahead, with its roadmap module.

02

Zoom in: how one feature request moves through the system

Every request — for either stream — takes the same six-hop path. Claude never touches disk directly: it returns a plan, and FeatureForge's own code decides whether and how to apply it.

03

One pipeline, two streams — and a boundary between them

fullstack and k8s run through the exact same plan → diff → apply code. Only two things change per stream: which directory it's allowed to write to, and which system prompt Claude receives. The write boundary is enforced in code, not convention.

04

Module 12: two stretch goals, same pipeline underneath

Neither of these changes the plan → diff → apply mechanism from Fig. 1 — streaming changes how the response is delivered; custom streams change how a stream's config is looked up. Same core code either way.
